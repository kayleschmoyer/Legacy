# FLD-001 — Native League Chat Tab is missing @mentions, system messages, and offline queueing promised by the feature spec

**Severity:** Medium
**Type:** Task
**Agent lens:** Senior QA Lead
**Platform:** Android Native
**File:** `apps/app/src/features/leagues/LeagueChatTab.tsx`, `apps/app/src/features/leagues/hooks/useLeagueChat.ts`

## Description

The Chat Tab Feature Story (LS-5415) describes: "Real-time LeagueChatTab with message list, input with send, system messages, @mentions, and WebSocket-driven updates; push notifications on Android background, keyboard-avoiding input, offline queueing." The implementation delivers the message list, text/GIF send, and keyboard-avoiding input, but grepping `LeagueChatTab.tsx` and `useLeagueChat.ts` for mention handling, a system-message rendering path, or any offline-queue/retry logic turns up nothing — only plain text and GIF messages are rendered, and there's no distinct system-message styling or metadata field on the message type. There is also no push-notification wiring visible in this component (may exist at the OS/notification-service layer outside this file — not verified here).

## Steps to Reproduce

1. Open the football (or baseball) league detail page, Chat tab, on native.
2. Type `@` followed by a teammate's name.
3. Observe there is no autocomplete, highlighting, or notification behavior distinguishing it from plain text.
4. Send a message while offline (airplane mode) and note there is no queued-send/retry indicator — the send simply fails or the `wsError` banner shows, with no local queueing.

## Expected

Per the Feature Story: @mention autocomplete/highlighting, distinguishable system messages (e.g. "X joined the league"), and offline message queueing that sends once connectivity returns.

## Actual

Only plain-text and GIF messages exist; no mention parsing, no system-message type, no offline queue.

## Recommendation

Scope as a follow-up feature ticket (not a one-line bug fix) — @mentions and offline queueing are each non-trivial: mentions need a lookup against league team members and message-schema support server-side; offline queueing needs a local persistence layer. Recommend running `/define` on the split-out scope before implementation rather than treating this as a single small PR.
