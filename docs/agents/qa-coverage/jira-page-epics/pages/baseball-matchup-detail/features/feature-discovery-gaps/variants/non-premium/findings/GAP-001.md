# GAP-001 — Missed feature: AI Matchup Recap panel undocumented as its own feature

**Severity:** Medium
**Type:** Bug
**Agent lens:** Feature Discovery From Code
**Platform:** All (web, mobile-web, android)
**File:** `lib/shared-components/src/features/matchup/MatchupRecapPanel.tsx`

## Description

`MatchupDetailLayout` renders a `recapPanel` slot (slot 8 of 9) wired on both platforms:
`apps/web/src/pages/matchup/MatchupDetailPage.tsx:250-260` and
`apps/app/src/features/matchup/screens/MatchupDetailScreen.tsx:147-157`. Both wrap
`MatchupRecapPanel` in a `PremiumGate` keyed on `canSeeRecap =
useHasEntitlement(ENTITLEMENTS.ai_matchup_recap)` (web: `MatchupDetailPage.tsx:71`; app:
`MatchupDetailScreen.tsx:44`).

The panel only renders when `matchup.status === MatchupStatus.Completed`. It fetches via
`useGetMatchupRecapQuery` with `fetchPolicy: 'cache-and-network'`
(`MatchupRecapPanel.tsx:44-52`, cites LS-5875 for why cache-first is unsafe across an
entitlement flip), shows a spinner while loading, a retryable `ErrorState` on fetch
failure (`MatchupRecapPanel.tsx:71-80`, cites BMD-007 for why "error" must not collapse
into the same empty state as "not generated yet"), an `EmptyState` when
`data.getMatchupById.recap` is `null` (`MatchupRecapPanel.tsx:82-91`), and otherwise a
card with headline/narrative/highlights plus BLOWOUT / CLOSE GAME badges driven by
`matchupType` (`MatchupRecapPanel.tsx:93-151`).

Server side, the `recap` field is null-gated on the same entitlement in
`lambdas/db/src/schema/matchups/types.ts:149-164`, and this is already tracked in
`docs/architecture/premium-gating-inventory.md:98` ("AI Matchup Recap ...
MatchupDetailPage (web), MatchupDetailScreen (app)") and
`docs/product/subscription-tiers.md:53`.

`MatchupDetailLayout.tsx:21-25,46-51,64-67,133-137` documents `recapPanel` as slot 8 of 9
in the page's fixed render order (after `rosterEditor`, before `rosterComparison`),
confirming this is a first-class, permanently-wired feature of the page rather than
incidental scaffolding.

None of the four pre-existing feature docs (matchup-information-card LS-5352,
matchup-navigation-controls LS-5353, roster-comparison LS-5357, win-probability-panel
LS-5358) cover this panel; `matchup-navigation-controls/feature.md` only mentions it in a
passing aside that "the gated panels on this page, Win Probability and AI Recap, are
separate features" — i.e. the existing docs already know it exists but no doc/ticket
owns it.

## Steps to Reproduce

1. As a non-premium user, open a `Completed` baseball matchup on `/baseball/league/:leagueId/matchups/:matchupId`.
2. Observe the "AI Matchup Recap" `PremiumGate` upsell card rendered in the recap slot.
3. As a premium user (`ai_matchup_recap` entitlement), open the same matchup and observe
   the loading spinner, then the recap card (or the "Recap not generated yet" empty state).

## Expected

A dedicated Feature Story enumerates the "AI Matchup Recap" panel: the
`PremiumGate`/entitlement wiring, the `Completed`-status gate, loading/error/empty
states, and the BLOWOUT/CLOSE GAME badge behavior — the same level of QA coverage as
the sibling win-probability-panel doc (LS-5358).

## Actual

No feature doc or Jira ticket owns this panel. It is invisible to the QA inventory
despite being a permanently-wired, first-class slot in `MatchupDetailLayout`.

## Recommendation

File a Feature Story for "AI Matchup Recap" (entitlement `ai_matchup_recap`,
`lib/utils/src/lib/entitlements.ts:44,87,115`; server gate
`lambdas/db/src/schema/matchups/types.ts:149-164`) modeled on the sibling
win-probability-panel doc (LS-5358), enumerating the PremiumGate wiring and all
loading/error/empty/success states.
