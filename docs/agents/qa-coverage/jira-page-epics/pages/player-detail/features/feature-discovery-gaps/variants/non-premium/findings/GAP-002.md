# GAP-002 — Missed feature: Shared PlayerDetailById component used cross-platform (web/native parity surface)

**Severity:** Medium
**Type:** Bug
**Agent lens:** Feature Discovery From Code
**Platform:** All
**File:** `lib/shared-components/src/features/players/PlayerDetail.tsx`

## Description

The native player detail screen (`apps/app/src/app/(app)/(tabs)/(home,leagues,players,games,you)/PlayerDetail.tsx`) delegates
entirely to `PlayerDetailById` from `lib/shared-components` — a cross-platform Tamagui
component that renders the same stat sections (Batting Statistics, Pitching Statistics)
on both web and native. The original QA inventory (LS-5578..5589) was written against
the web `PlayerDetailModal` journey and never noted this shared-lib dependency. As a
result, a regression to `PlayerDetailById` in `lib/shared-components` silently breaks
the native player detail surface without any web-side signal in CI or E2E tests.

No feature document calls out `shared-component-cross-platform-render-parity` for the
player detail page — meaning the parity contract between native and web is implicit and
untracked.

## Steps to Reproduce

1. Render `PlayerDetailById` on native (`apps/app`) for a known `playerId`.
2. Compare visible sections with the web `PlayerDetailModal` for the same player.
3. Observe that the native render path goes through the shared lib, not the editorial
   web component, so section availability and stat labelling can diverge undetected.

## Expected

The `player-detail-modal` Feature Story (LS-5585) — or a dedicated cross-platform
parity variant — enumerates the shared-component render path and notes that the native
surface is covered by `PlayerDetailById`, so any regression to that component is
immediately attributable to the native player detail journey.

## Actual

The shared dependency is implicit. The `player-detail-modal` feature doc (LS-5585)
only describes the web `PlayerDetailModal` journey; the native `PlayerDetailById`
surface has no QA inventory entry documenting its component boundary or parity contract.

## Recommendation

Add a `cross-platform-render-parity` note under the `player-detail-modal` feature
story. The note should enumerate:

- Which platform uses which component (`PlayerDetailModal` on web,
  `PlayerDetailById` on native)
- The sections present in `PlayerDetailById` (Batting Statistics, Pitching Statistics)
- The regression risk: a change to `PlayerDetailById` affects native only; it is not
  caught by the web E2E suite

## Resolution

- Cross-platform parity variant documented in
  `docs/agents/qa-coverage/jira-page-epics/pages/player-detail/features/player-detail-modal/feature.md`
  under the **Cross-Platform Render Parity** section.
- The section enumerates: web entry point (`PlayerDetailModal`), native entry point
  (`PlayerDetailById`), the sections native renders (Batting Statistics, Pitching
  Statistics), and the regression-risk callout.
- Unit tests for the native screen already assert that `PlayerDetailById` is mounted
  when valid and invalid `playerId` params are supplied
  (`apps/app/src/app/(app)/(tabs)/(home,leagues,players,games,you)/PlayerDetail.spec.tsx`).
