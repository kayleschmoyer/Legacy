# GAP-001 — Missed feature: Invalid/missing playerId param fallback (toIntId default 0)

**Severity:** High
**Type:** Bug
**Agent lens:** Feature Discovery From Code
**Platform:** Android Native
**File:** `apps/app/src/app/(app)/PlayerDetail.tsx:18`

## Description

`id` defaults to `0` when `toIntId` returns `null` —`PlayerDetailById(playerId=0)` is
then rendered, likely hitting the backend with an invalid ID and displaying an empty or
error state with no user-visible explanation. The `deep-link-from-many-surfaces` feature
story (LS-5581) covers valid deep-link entry points but does not enumerate malformed
deep-link recovery (missing param, non-numeric value such as `?playerId=abc`).

## Steps to Reproduce

1. On an Android / iOS device, open the deep link `/player?playerId=abc`
2. On an Android / iOS device, open the deep link with the `playerId` param entirely absent

## Expected

A `invalid-deep-link-fallback` variant shows a friendly error state (e.g. "Player not
found") and a Back action that returns the user to the players list.

## Actual

Silent fallback to `playerId=0`; backend query fires with an invalid ID; UX outcome
is unclear (empty state, spinner, or silent error).

## Recommendation

Add an `invalid-deep-link-fallback` variant under the deep-linking feature story
(LS-5581); consider an explicit guard in `PlayerDetailScreen` that redirects to the
players list when `toIntId` returns `null`.
