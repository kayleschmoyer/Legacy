# GAP-003 — Missed feature: Kicker (K) stats table with computed FG% (fgm / fga \* 100)

**Severity:** Medium
**Type:** Bug
**Agent lens:** Feature Discovery From Code
**Platform:** Web
**File:** `lib/shared-components/src/features/football/FootballPlayerDetail.tsx:726`

## Description

`OffenseStatsTable` renders a position-specific career stat group. When the kicking
category has data it renders `KickingStatGroup`, which surfaces field-goal
percentage (FG%) from the server-authoritative `kicking.fgPct` (LS-6244):

```ts
const fgPct = k?.fgPct ?? null;
// ...
<StatCell label="FG%" value={fmtFloat(fgPct)} />
```

FG% used to be recomputed client-side from `fgm`/`fga` in three display sites;
LS-6244 made the server the single source of truth (`fgPct` is `null` when there
are no attempts), so the high-risk division-by-zero / null-safety logic now lives
server-side and the table simply formats the provided value. `fmtFloat` renders
`—` for `null` (0-attempt kickers), and the group is only rendered when
`hasAnyValue(kicking)` is true — so a `null` kicking object renders nothing at all.
The rendered output is correct, but the behavior appeared in **no Feature Story**.
The existing breakdown story (LS-5435)
enumerates Passing / Rushing / Receiving only; Kicking is rendered but was untracked.
The detail view is shared (`lib/shared-components`) but consumed only by the Web page
(`apps/web/src/pages/football/FootballPlayerDetailPage.tsx`) — there is no native
football player detail screen, so this gap is Web-scoped.

## Steps to Reproduce

1. Navigate to a kicker, e.g. `/football/players/<K_id>`, who has `fga = 0`
   (a rookie or preseason kicker with no attempts yet).
2. Observe the "Career Kicking" stat group (FGM / FGA / FG%).

## Expected

- A documented Feature Story / QA inventory entry covers the Kicker (K) stats table.
- 0-attempt kickers (`fga = 0`) do not render `NaN%` — FG% shows `—`.
- FG% formats to 1 decimal place (e.g. `90.0`).

## Actual

The Kicker (K) stats table was untracked in the QA inventory, and the null/zero
edge had no regression test, leaving it unguarded by QA even though the code
handles it correctly.

## Recommendation

Document the kicker stats breakdown as part of this feature-discovery-gaps bucket
and add regression coverage for the FG% computation. Extend the breakdown
inventory to list K (and, separately, IDP / DST) as explicit variants.

## Resolution

`KickingStatGroup` (`FootballPlayerDetail.tsx:726`) renders the server-provided
`kicking.fgPct` (LS-6244) via `fmtFloat`, which defaults to 1 decimal place and
renders `—` for `null` (the server returns `null` for zero-attempt kickers). No
production code change was required.

Regression coverage was added in `FootballPlayerDetail.spec.tsx` (LS-7639):

- A standard kicker (`fgm = 27`, `fga = 30`, `fgPct = 90`) renders FGM / FGA and
  FG% `90.0` (1-decimal format).
- A 0-attempt kicker (`fga = 0`, `fgPct = null`) renders FG% `—` rather than `NaN%`.
- A kicker with `null` kicking stats omits the Career Kicking group entirely
  (`hasAnyValue` is false) without throwing.

These tests lock in the AC2 (no `NaN%`) and AC3 (1-decimal format) behavior so a
future regression is caught by QA.
