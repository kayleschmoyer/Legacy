# TC-001-P — useGetUserLeaguesQuery returns ALL user leagues but does not filter for leagues in active phase — selector shows leagues where trading is impossible

**Severity:** High
**Type:** Bug
**Agent lens:** Code audit
**Platform:** All
**Jira:** LS-7484

## Description

`useGetUserLeaguesQuery` returns every league the authenticated user belongs to —
the GraphQL resolver applies no `leaguePhase` filter server-side. The Trade Center
page must filter the result client-side to `leaguePhase === 'active'` before
rendering the league selector.

Without the client-side filter, premium users can tap into a pre-draft or offseason
league in the selector, load the team roster, and only discover that trading is
disabled after the `proposeTrade` mutation fails server-side (it gates on
`leaguePhase === 'active'`).

## Steps to Reproduce

1. Authenticate as a premium user who belongs to leagues in multiple phases
   (e.g. one `active`, one `pre-draft`, one `offseason`).
2. Navigate to `/trade-center`.
3. Observe the league selector.

## Expected

Only `active`-phase leagues appear in the league selector. Pre-draft, offseason, and
live-draft (pre-draft + `draftStatus === 'in-progress'`) leagues are hidden.

## Actual

(At time of filing) All leagues appeared regardless of phase, allowing users to
select leagues where `proposeTrade` will reject the request.

## Fix

`TradeCenterPage.tsx` line 422:

```typescript
const leagues = allLeagues.filter((l) => l.leaguePhase === 'active');
```

This client-side filter is applied to all users (premium and non-premium).

## Regression Tests

`TradeCenterPage.spec.tsx` — `describe('premium variant — active-phase filter (TC-001-P)')`:

- Shows only active leagues when user belongs to leagues across all phases
- Shows empty-state message when user has no active-phase leagues
- Shows live-draft league as filtered out (pre-draft phase, draftStatus in-progress)
