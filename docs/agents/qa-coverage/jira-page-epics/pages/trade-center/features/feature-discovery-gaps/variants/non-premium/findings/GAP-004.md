# GAP-004 — Missed feature: Stale-player warning on incoming trade offers

**Severity:** Medium
**Type:** Bug
**Agent lens:** Feature Discovery From Code
**Platform:** Web + Android Native
**File:** `lib/shared-components/src/features/leagues/TradingCenter.tsx:249`

## Description

When a trade offer is incoming and pending, `TradeOfferCard` lazily fetches the
proposing team's current roster (`useGetTeamMembersLazyQuery`) and cross-references
it against the players listed in the offer. If any offered player is no longer on
the proposing roster (they were dropped after the trade was proposed), the component:

1. Strikes through the stale player's name in red and shows an `AlertTriangle` icon.
2. Renders a red warning banner: "One or more offered players are no longer on this
   team's roster. Accepting will fail."
3. Disables the "Accept" button to prevent a mutation that would fail on the backend.

A second guard also fires when the roster fetch itself errors: a separate banner
("Unable to verify this team's roster. Accepting is disabled.") is shown and Accept
is disabled as a safety fallback.

Neither the stale-player warning path nor the roster-fetch-error path appears in the
existing feature stories (`trade-center-overview` LS-5680, `submit-new-trade`
LS-5678).

## Steps to Reproduce (stale player)

1. User A proposes a trade to User B, including Player X.
2. User A then drops Player X from their roster.
3. User B opens the Trade Center — observe the Accept button on that offer.

## Expected

Player X row shows strikethrough red text + AlertTriangle icon, warning banner is
displayed, "Accept" button is disabled.

## Actual

No QA coverage for this scenario exists in the inventory.

## Recommendation

Add acceptance criteria to `trade-center-overview` (LS-5680) or create a dedicated
Feature Story covering:

- Stale-player visual indicator (strikethrough + icon)
- Warning banner text
- Accept disabled when stale players are present
- Roster-fetch-error banner + Accept disabled fallback
