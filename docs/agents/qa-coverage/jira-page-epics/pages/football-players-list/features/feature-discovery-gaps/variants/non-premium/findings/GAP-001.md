# GAP-001 — Missed feature: Cursor-based pagination with 'Load more' button and append-vs-replace mode

**Severity:** High
**Type:** Bug
**Agent lens:** Feature Discovery From Code
**Platform:** Web
**File:** `apps/web/src/pages/football/FootballPlayersPage.tsx:71`

## Description

FootballPlayersPage maintains accumulated allNodes via cursor/endCursor and a
prevCursorRef. When cursor changes, results are appended; when filters change,
allNodes is reset and cursor cleared (line 47). This is non-trivial state-machine
code (race condition prone — what if a filter change races a cursor fetch?). No
Feature Story enumerates 'Load more', infinite scroll behavior, or the
append/replace state-machine.

## Steps to Reproduce

1. Navigate to /football/players
2. Scroll to bottom and click 'Load more'
3. Mid-load, change position filter to 'QB'

## Expected

Documented story; results don't get into a mixed appended-then-filter-replaced state.

## Actual

Untracked race; users could see ghost entries from the previous filter merged into
the new filtered set.

## Recommendation

Create Feature Story 'nfl-players-pagination-load-more' covering filter-during-load
races, end-of-list state, and error mid-pagination.
