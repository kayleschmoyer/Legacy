# GAP-003 — Missed feature: View-mode toggle (cards/table) persisted to localStorage with responsive default

**Severity:** Low
**Type:** Bug
**Agent lens:** Feature Discovery From Code
**Platform:** Web
**File:** `apps/web/src/pages/football/FootballPlayersPage.tsx:40`

## Description

FootballPlayersPage exposes a view-mode toggle that switches the player list between
a card grid and a table layout (the `LayoutGrid` / `LayoutList` buttons, lines
511-531). The selection is persisted to localStorage under the key
`football_players_view_mode` (line 40) and re-hydrated on mount (lines 356-374). When
no stored preference exists, the default is chosen responsively — `cards` on
mobile/tablet (`media.sm`, maxWidth 800) and `table` on desktop. The table layout
itself was requested by FPL-027 (LS-6474), but no Feature Story enumerates the
_persisted, user-selectable toggle_ or the responsive default-selection logic, both
of which have their own failure modes (stale/invalid stored value, localStorage
access throwing in private-browsing/SSR contexts, default not matching the viewport
on first paint).

## Steps to Reproduce

1. Navigate to /football/players on a desktop viewport — observe the default table view.
2. Click the cards (grid) toggle, then reload the page — the cards view persists.
3. Open the page in a context where `localStorage` access throws (e.g. hardened
   private browsing) — the read/write is wrapped in try/catch (lines 357-373) and
   should silently fall back to the responsive default.

## Expected

A Feature Story covering: persisted view-mode round-trip, responsive default when no
preference is stored, and graceful fallback when localStorage is unavailable.

## Actual

No story; view-mode persistence and responsive-default defects (e.g. wrong default on
first paint, lost preference, crash on localStorage access) would not be caught.

## Recommendation

Create Feature Story 'nfl-players-view-mode-toggle' with variants for: stored
preference round-trip, responsive default (mobile vs desktop), and localStorage-
unavailable fallback.
