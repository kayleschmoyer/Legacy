# GAP-001 — Missed feature: Navigator.share fallback chain (share -> clipboard -> manual)

**Severity:** High
**Type:** Bug
**Agent lens:** Feature Discovery From Code
**Platform:** Web
**File:** `apps/web/src/pages/players/PlayerStatsPage.tsx:431`

## Description

`handleShare` uses a three-tier fallback: `navigator.share` (Web Share API) ->
`navigator.clipboard.writeText` -> manual-copy message. `AbortError` on share
dismissal is silently swallowed. The `share-current-view` feature exists in code
but does not enumerate these three branches as separate variants, nor a
browser-support matrix (Safari iOS supports share, desktop Chrome falls back to
clipboard).

## Steps to Reproduce

1. Open the Player Statistics page in Safari iOS and share (Web Share API).
2. Open the page in desktop Chrome and share (clipboard fallback).
3. Open the page in a browser blocking the clipboard (manual-copy message).

## Expected

Feature has variants for `share-api-available`, `clipboard-fallback`, and
`manual-copy-message`.

## Actual

A single, undocumented `share-current-view` branch with no enumerated variants
and no browser-support matrix.

## Recommendation

Split `share-current-view` into three variants per fallback branch.

## Resolution

Enumerated under LS-7659. The `share-current-view` feature is now documented at
`../../../../share-current-view/feature.md` with the three fallback variants
(`share-api-available`, `clipboard-fallback`, `manual-copy-message`), a
browser-support matrix, and a note that the `AbortError` (share-sheet dismissal)
swallow is intended behaviour. No code change was required — `handleShare`
already implements the fallback chain correctly; the gap was in feature
enumeration only.
