# E2E dual-mode migration matrix (LS-9674)

Pricing analysis for [LS-9663](https://legacy-sports.atlassian.net/browse/LS-9663) (epic: dual-mode
convergence). Every spec under `apps/web-e2e/src/integration/tests/` (24 files) was read in full and
scored against the ADR-0016 backend seam (`apps/web-e2e/src/fixtures/dual.ts` +
`apps/web-e2e/src/fixtures/test-data.ts`). See
[ADR-0016](../decisions/0016-test-dependency-injection.md) and the
[testing skill](../../.agents/skills/testing/references/test-architecture.md#test-dependency-injection-adr-0016) for the
mechanism itself.

## TL;DR

- **5 of 24 specs are not dual-mode candidates at all** — see [Excluded](#excluded-specs-not-dual-mode-candidates).
- **2 structural gaps block the majority of the remaining 19.** Neither is a per-spec `TestData` verb —
  both are one-time extensions to the seam itself. See [Seam extension list](#testdata-seam-extension-list).
- **3 specs already migrated for free** (no new verb, no fixture gap) before this ticket:
  `league-discovery-search`, `player-compare-search`, `player-stats-search` (the 3 existing templates).
  Of the 24 specs in scope here, `player-search-stats-ui.integration.spec.ts` is one query away from
  being fully retired (S) — see row 15.
- Real end-to-end multi-actor sagas (waivers, trades, full season, playoff bracket) are **expensive to
  mock faithfully** — several are recommended as _partial_ migrations (UI-mechanics slice moves, the
  business-logic-correctness assertions stay live-only) rather than full ports.

## How to read this table

- **Flows** — one line per `test()` block in the spec.
- **TestData gaps** — precondition(s) the existing 5 verbs (`playerPool`, `discoverySearch`,
  `pitchingLeaders`, `comparablePlayer`, `footballLineup`) cannot express, and what new verb(s) would be
  needed. Verbs marked "shared" appear once in the [seam extension list](#testdata-seam-extension-list)
  and are cross-referenced from every spec that needs them.
- **Live-only assertions** — content that must stay in a **residual integration spec** even after
  migration (real OAuth, real Stripe, real websocket push, real async Lambda races, real external
  datasets). A spec with live-only content is not fully retired by migration — only its UI-mechanics
  slice moves to `src/tests/shared/`.
- **Size** — S (verb(s) exist or trivial to add, few tests) / M (2-4 new verbs, moderate statefulness) /
  L (deep multi-phase precondition, large stateful mock, or a structural fixture gap must land first).
- **Priority** — per the epic's stated order (incident-history first: waivers → matchup/roster → trades
  → subscription gating → season lifecycle last), with other flows interleaved by judgment.

## Recommended migration waves

Per the epic's stated priority (incident-history first: waivers → matchup/roster → trades →
subscription gating → season lifecycle last), tempered by dependency order (structural gaps must land
before the specs that need them) and by pulling forward genuinely cheap wins:

- **Wave 1** — seam foundation + cheapest wins. Child ticket filed: seam extensions #1
  (`multiActorPage`) + #2 (seeded-league verb family) as one prerequisite ticket, since most later
  waves depend on both; plus a second ticket bundling the specs that need **no** structural gap at all
  (#15 player-search-stats-ui, #13 league-qr-invite-ui, #14 league-scoring-editor-ui, #8's Phase-6
  dialog slice).
- **Wave 2** — waivers + matchup/roster (the epic's explicit incident-history priority), building on
  Wave 1's seam: #1 waiver-processing-ui (partial), #3 matchup-roster-editor-ui, #2 matchup-detail-ui.
- **Wave 3** — trades + remaining league-admin flows: #6 trade-flow-ui, #10/#11 commissioner
  announcements/settings, #12 league-activity-feed-ui.
- **Later waves (not filed yet)** — #7 subscription-gating (UI slice only), #4/#5/#19
  roster/recap/playoff-bracket, #16/#17/#18 draft-board/live-draft/mock-draft (each has a
  live-only-by-design core), #9/#8 full-season/season-renewal sagas (season lifecycle, explicitly last
  per the epic).

Child tickets for waves 1-3 are filed under LS-9663 — see ticket comments on LS-9674 for the keys.
