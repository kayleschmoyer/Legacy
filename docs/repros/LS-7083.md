- Results (savesOnMount / savesAfterClick): plain 0/1, plain+hydrate 1/2, strict 1/2, strict+hydrate 2/3, strict+suspense 1/2, strict+suspense+hydrate 2/3 - the click always adds a save with the user's value

**Attempted steps**: See attached steps in the investigation notes.

**Hypotheses**:

- Ref could still be true at the first user action: not possible. The effect runs after the mount commit and React flushes passive effects before dispatching a discrete user event, so the ref is flipped before any click can be handled
- StrictMode double-effect: the second (dev-only) run sees ref=false and performs one redundant savePrefs(initialPrefs) + 'Saved' flash on mount. This is a spurious extra save of unchanged values, the opposite of a swallowed save, and dev-only
- Suspense: a suspended render never commits, so its state and ref are discarded; the committed instance runs the mount effect normally
- HMR/Fast Refresh: effects re-run with refs preserved (false), so at worst an extra save, never a skipped one
- Mount-time hydration (theme sync, server statsFormat/audioEnabled) calls setPrefs in mount effects and triggers a save of hydrated values; this is not a swallowed user action and is benign

**Recommendation**: Close as not reproducible / no defect: 'First user-driven change always saves' holds on current main. Recommendation to use a hasUserInteracted flag is not needed; it would also not remove the dev-only StrictMode extra mount save, which is harmless. No code change.
