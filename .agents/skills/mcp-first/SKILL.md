# Skill: MCP-First

> **MCP-first principle**: the shell commands shown in AGENTS.md (Workflow, Commands sections) are **fallbacks** for when MCP servers are unavailable. When MCP tools are available, always prefer them.

## Environment Detection

Never assert which environment you are in from prose — probe the actual tool surface with `ToolSearch` and route accordingly:

| Probe (`ToolSearch` query)            | Present means                                            | Absent means                                                                                                                                                                                                                                                                                                                                                                                     |
| ------------------------------------- | -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `select:worktree_ping`                | stdio servers running (local, or cloud with working tsx) | no stdio servers → run [diagnostics](references/diagnostics.md) Check 1 first                                                                                                                                                                                                                                                                                                                    |
| `select:github_auth_status`           | hosted `legacy-sports-github` connector connected        | connector not consented/registered → [Auth Model](references/auth-and-routing.md#auth-model)                                                                                                                                                                                                                                                                                                     |
| `select:nx_run_pc_chunk`              | pc-chunk validation via MCP is **mandatory**             | run [diagnostics](references/diagnostics.md) Check 1 first — absence is not exclusively a cloud/degraded signal; it recurs in local Windows launcher-worktree sessions too (LS-8774, LS-9743). Only fall back to the background-Bash chunk path (see [Validation Routing](references/auth-and-routing.md#validation-routing)) after diagnosing/reporting per diagnostics.md's reporting protocol |
| `select:mcp__github__get_me`          | CC-web built-in GitHub tools available                   | not on this platform (e.g. Copilot)                                                                                                                                                                                                                                                                                                                                                              |
| `select:mcp__ccd_session__spawn_task` | chip dispatch available                                  | chips unavailable → see [spawn_task](references/auth-and-routing.md#spawn_task-and-chips)                                                                                                                                                                                                                                                                                                        |

### Whole-session absence is expected in some session types, not just transient failure (LS-9320)

AGENTS.md's "shell fallback" language reads as if MCP tools normally exist and occasionally fail on a given call. That framing is incomplete: for `worktree`/`legacy-sports-nx`/`legacy-sports-make` (and sometimes their siblings — `legacy-sports-aws`/`browser`/`dev-process`/`ci-local`/`stripe`), **total absence for the entire session** — not one flaky call, not a mid-session drop — is a recurring, documented pattern in specific session types. If a probe from the table above comes back absent, do not treat that as a one-off before checking whether your session type is a known case:

| Session type                                            | What's absent, for how long                                                                                                                                                         | Sanctioned fallback (compliant, not a stopgap)                                                                                                                                           | Canonical reference                                                                                                                                                                                                                                    |
| ------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| CCR (Claude Code Remote) direct-branch / cloud sessions | `worktree`, `legacy-sports-nx`, `legacy-sports-make` (often the whole stdio cohort) `CONNECT_TIMEOUT`/`CONNECTION_CLOSED` at session start, no self-heal for the session's lifetime | Raw `git status`/`add`/`commit`/`push`/`fetch`/`diff`/`merge` via Bash; `pnpm exec nx run <project>:<target>` or backgrounded `make pc-<chunk>` in place of `nx_run_pc_chunk`/`make_run` | [diagnostics.md § LS-8689](references/diagnostics.md#persistent-whole-session-non-connection-in-ccr-direct-branch-sessions-ls-8689)                                                                                                                    |
| Local Windows launcher-worktree sessions                | Same stdio cohort absent for the whole session even with `node_modules`/`tsx` confirmed healthy (rules out the usual bootstrap-script cause)                                        | Same raw `git`/`make pc-<chunk>`/`npx nx` fallback as above                                                                                                                              | [diagnostics.md § LS-8774/LS-9743](references/diagnostics.md#persistent-whole-session-non-connection-in-local-windows-launcher-worktree-sessions-ls-8774)                                                                                              |
| Any session (hosted connectors specifically)            | `legacy-sports-jira`/`-github`/`-ci`/`-db`/`-rollbar` absent or `Incompatible auth server` at start, sometimes attaching only **after** the PR has already merged                   | `acli`/`gh`/REST fallback, **plus** a bare-name `ToolSearch` re-probe before each subsequent Jira/GitHub step (a late attach can land under a UUID-prefixed alias)                       | [§ Hosted connector late-attach](references/tool-surfaces.md#hosted-connector-late-attach-ls-9370), [diagnostics.md § LS-9439](references/diagnostics.md#mid-session-auth-server-incompatibility-does-not-support-dynamic-client-registration-ls-9439) |

In every row, the absence is platform/transport-side (confirmed via repo-side artifact checks in the linked tickets), not a repo misconfiguration to chase down mid-ticket. Diagnose once per the linked section's Check/Recovery steps, report per [diagnostics.md's Reporting Protocol](references/diagnostics.md#reporting-protocol), then proceed on the fallback for the rest of the session — that is the expected, compliant path, not something to apologize for or keep re-litigating on every subsequent tool miss.
