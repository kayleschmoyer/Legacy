# Skill: MCP-First

> **MCP-first principle**: the shell commands shown in AGENTS.md (Workflow, Commands sections) are **fallbacks** for when MCP servers are unavailable. When MCP tools are available, always prefer them.

> **Auto-mode carve-out (LS-9755)**: the harness's "auto mode" system directive tells agents to bias toward Bash (`cat`/`sed`/`grep`-equivalents) for efficiency, which on its face contradicts AGENTS.md's Tool Usage rule to prefer `Glob`/`Grep`/`Read` over raw shell. The two are reconciled by scope, not by one overriding the other wholesale:
>
> - **Plain file read/search operations** (a `cat`, `sed -n`, `grep`, `find`, `tail`, `wc -l` equivalent, with no MCP-domain semantics) — when auto mode is active, deferring to Bash for these is sanctioned. `Glob`/`Grep`/`Read` remain the default; auto mode only widens what's acceptable, it doesn't ban the dedicated tools.
> - **Everything else is unaffected** — MCP-first stays mandatory regardless of auto mode: `make_run` over `make`, `nx_run`/`nx_run_affected` over `pnpm exec nx`, `jira_*`, `github_*`, `worktree_*`, `db_*`, and every other domain operation in this skill. Auto mode's Bash-bias language is about plain file I/O, not a general license to skip MCP tools — read it narrowly.
>
> `ci_audit_session_bash`'s `auditMode` report detects the auto-mode directive in the session transcript and excludes the resulting FILE-READ/GREP-class `missing-awareness` findings (`find`/`grep`/`sed -n`/`tail`/`wc -l`) from `action_required`, surfacing them instead under `informational.auto_mode_excluded` — those calls are expected behavior in that mode, not a real awareness gap. Findings for domain-operation gaps (missing `make`/`nx`/`gh`/`jira`/`db` coverage, etc.) are never excluded by this — the carve-out only ever touches the plain-file-read/search class.

> **Label changes on a PR/issue**: use `github_manage_labels` (genuinely additive add/remove, safe no-op, works on PRs) — never `issue_write`'s full-set-replace, which can race-clobber a concurrently-removed `merge-when-ready`. Full guidance: [auth-and-routing.md § Label Change Routing](references/auth-and-routing.md#label-changes--always-additive-never-replace-semantics-ls-9715).
>
> **`issue_write` also can't target a PR number at all, for any field (LS-9692)** — a hosted-tool limitation, not a repo bug. Never call it with a PR number. Full guidance: [auth-and-routing.md § `issue_write` Cannot Resolve PR Numbers](references/auth-and-routing.md#issue_write-cannot-resolve-pr-numbers-ls-9692).

## Environment Detection

Never assert which environment you are in from prose — probe the actual tool surface with `ToolSearch` and route accordingly:

| Probe (`ToolSearch` query)            | Present means                                            | Absent means                                                                                                                                                                                                                                                                                                                                                                                     |
| ------------------------------------- | -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `select:worktree_ping`                | stdio servers running (local, or cloud with working tsx) | no stdio servers → run [diagnostics](references/diagnostics.md) Check 1 first                                                                                                                                                                                                                                                                                                                    |
| `select:github_auth_status`           | hosted `legacy-sports-github` connector connected        | connector not consented/registered → [Auth Model](references/auth-and-routing.md#auth-model)                                                                                                                                                                                                                                                                                                     |
| `select:nx_run_pc_chunk`              | pc-chunk validation via MCP is **mandatory**             | run [diagnostics](references/diagnostics.md) Check 1 first — absence is not exclusively a cloud/degraded signal; it recurs in local Windows launcher-worktree sessions too (LS-8774, LS-9743). Only fall back to the background-Bash chunk path (see [Validation Routing](references/auth-and-routing.md#validation-routing)) after diagnosing/reporting per diagnostics.md's reporting protocol |
| `select:mcp__github__get_me`          | CC-web built-in GitHub tools available                   | not on this platform (e.g. Copilot)                                                                                                                                                                                                                                                                                                                                                              |
| `select:mcp__ccd_session__spawn_task` | chip dispatch available                                  | chips unavailable → see [spawn_task](references/auth-and-routing.md#spawn_task-and-chips)                                                                                                                                                                                                                                                                                                        |

> **Whole-session tool absence (not just a flaky call) is a recurring, documented pattern in specific session types** — CCR/cloud, local Windows launcher-worktree sessions, and hosted-connector late-attach. If a probe above comes back absent, check whether your session type is a known case before treating it as transient: [diagnostics.md § Whole-session absence (LS-9320)](references/diagnostics.md#whole-session-stdio-absence-by-session-type-ls-9320).
