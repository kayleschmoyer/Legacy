### Local-only step nuances

- **Worktree-first; never edit code in `D:\code\legacy-sports` with HEAD on `main`.** All work happens in the active worktree.
- **Resuming PR work** (new session / after a context switch): call `worktree_set` before any git op, then use `worktree_diff` / `worktree_commit` / `worktree_push` — not raw `git -C <path> ...`.
- **Pre-push hook fails with `nx` not found / `ERR_PNPM_RECURSIVE_EXEC_FIRST_FAIL`**: `node_modules/.bin` is empty. Use `worktree_push({ skipLint: true })` as a temporary workaround — note `SKIP_PREPUSH_LINT=1` also skips the conflict-marker and Terraform checks, so run Prettier manually first (`node node_modules/prettier/bin/prettier.cjs --write <files>`) and check for conflict markers. Root cause: main-repo `node_modules/.bin` corruption; ask the user to repair it.
- **Check Runs vs Commit Statuses**: `github_retrigger_check` only operates on Check Runs. `bot-review` and similar bot statuses use the Statuses API — find them with `github_list_commit_statuses({ prNumber })`; clear a stale one by pushing a commit or dispatching the workflow, not `github_retrigger_check`.
- **`make_run`/`nx_run_pc_chunk`/other stdio MCP tools unavailable in a local session**: that is a **broken worktree**, not a degraded environment — stdio servers fail silently when `node_modules/.bin/tsx` is missing (broken `node_modules` link). Run `node scripts/modules-pool/link.mjs` from the worktree root, then ask the user to restart the session so the servers reconnect. Do **not** fall back to the cloud degraded path (background-Bash `make pc-<chunk>`) in a local session — that fallback is sanctioned only for default CC web, and its end-turn-and-wait-for-notification pattern is the stall vector that abandoned PR #6190 mid-validation (LS-8542).
- **Stepwise validation (default everywhere, not just timeout-prone sessions)**: run the seven `pc-*` chunks (`pc-db-prep` → `pc-typecheck` → `pc-lint` → `pc-format` → `pc-workflows` → `pc-test` → `pc-build`) **in order** — equivalent to `make pc` only if all seven run. Update the continuation checkpoint after each. Locally each chunk is `make_run({ target: "pc-<chunk>" })`. Cloud sessions bind the same chunks differently (`nx_run_pc_chunk` when present — mandatory; degraded CC web falls back to background Bash chunks): see the [spine's binding table](ticket-to-merge-spine.md#tool-binding-by-environment) and [cloud-agent-mode](../../cloud-agent-mode/SKILL.md) — monolithic `make pc` is never valid in cloud. It's not just cloud: LS-8797 observed a backgrounded monolithic `make pc` hang for 40+ minutes with zero output in an ordinary local Windows session that had never been flagged timeout-prone, so default to the chunks locally too — reserve `make_run({ target: "pc" })` for a foreground run you're actively watching, never backgrounded.
